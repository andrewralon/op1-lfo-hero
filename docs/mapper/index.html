op1 lfo hero

device report  ·  guided mapper  ·  ~10 minutes

nothing is uploaded. everything happens in your browser. the only thing that leaves this page is a file you download and choose to send.

what this does

lfo hero drives the op-1 field, with tx-6 and tp-7 support in testing. each was mapped by measuring real hardware, because the published midi references turned out to be wrong in at least six places.

to support any other teenage engineering device — op-1 (original), op-z, ep-133, ob-4, po series — someone who owns one has to record what it actually sends. this page walks you through it. you don't need to know anything about midi.

it only listens, unless you explicitly opt in to the optional send tests near the end.

plug your device in over usb, then:

your browser will ask permission, possibly twice (once for midi, once for sysex). both are needed. prefer a monitor you already trust? manual instructions.

this browser can't do it

this page needs the web midi api, which needs chrome, edge or firefox on a computer. safari has never supported it, on mac or on iphone/ipad — so there is no version of this page that would work here.

1 — what's connected

one standard midi identity question — safe on any device

2 — listen while you do nothing

some devices talk constantly, some say nothing until you touch them. both are useful to know. don't touch the device for the next 20 seconds.

3 — about your device

if it has no per-track mixer at all, set this to 1.

4 — capture

5 — send tests (optional)

everything so far only listened. these tests send midi to your device to find out whether it responds to what it transmits — which decides whether the app can control it at all. it's the single most valuable optional thing you can do.

but it does change things on your device.

  • save or stop anything you're working on first
  • we only replay controls your device itself just sent, never unknown ones
  • we never send record-arm, and never cc 120 unless your own mute used it
  • faders and knobs may move; the transport may start and stop

6 — last questions

7 — send it

message andrewralon on op-forums.com: open a message on op-forums

the summary is enough — it's short, and pasting it straight into the message needs no file attachment at all, which matters if your forum account is new. attach the full report too if you can; it holds every raw byte, so a reading can be checked later rather than taken on trust.

would rather use github? open an issue and attach it there instead.

thank you — genuinely. this is the only way devices we don't own ever get supported.
